4  Non-deterministic Finite Automata (NFAs)

This chapter discusses strategies for understanding and working with non-deterministic finite automata (NFAs). We will cover the basics of NFAs, including their definition, how to construct them, and how to use them to recognize languages. We will be using examples and exercises to help practice and solidify our understanding of NFAs. By the end of this chapter, we should have a good grasp of what NFAs are, how they work, and how to use them effectively.

4.1 Non-deterministic Moves in Finite Automata

As yet another extension of expression in finite automata, we introduce some potentially non-deterministic moves to our deterministic finite automata. These moves may allow a pathway to split or fall off the machine. Sometimes we mention multiple paths as guesses or parallelism. We will use this chapter to introduce those ideas in pieces. First, let’s introduce a new transition symbol. We call this a free transition and it is denoted in our book as ~. Thus, when you see a ~ transition, that transition can be taken without consuming an input symbol. Let’s look at a simple example in Figure 4.1.

In Figure 4.1 we notice that we stay in state A when we see inputs of a’s and we stay in state B when we see inputs of b’s. However, the transition between A and B is a free transition, ~. This means, that we may take this transition whenever we like. The best way to think of this processing is that ~ jumps are taken immediately and whenever possible. This does mean that a machine can be in more than one state at a time. When we start the machine we are in the states A and B, or written as a set, {A,B}. If the input string is “ab”, the next step needs to consume an a. When we do that, A takes us to state A and B falls off the machine (a non-deterministic move). This leaves us in state A, but the free jump allows us to go back to state B again immediately. So, on an a, this machine leaves us back in the set {A, B}. When we read a b, state A has no b transition and thus that pathway falls off the machine. However, state B leaves us back to B, so we’re now in state B or the set of states is now just {B}. Now that we’re done processing this string, one of the paths led us to an accept, so we would accept the string “ab”. We’ll explore this in the following exercise.

In Figure 4.1 we saw a machine that uses a free transition, free jump, or ~, to create a situation where processing the machine requires us to think of being in multiple states at once. However, in an NFA, intentional parallelism can also be created by forking the processing of an input character to multiple states. In other words, imagine a state in which a transition occurs on an input symbol to more than one state. Let’s look at a small example again as seen in Figure 4.2.

Figure 4.2 demonstrates that we make transition from A on a 1 to two different states. If the input is “111” then the first 1 is consumed and leaves us in the states {B,C}. Just like before with a free transitions, we’re in aprocessing situation in which we may need to process multiple paths. If any of these paths succeed, then the string is accepted. In this case, 111 takes us from A to {B,C} to {D} and then to {D} to finish the processing. The bottom path ends in an accept state and thus we accept this string. Let’s explore this machine in the following exercise.

These types of transitions are often useful when we would like to process two different paths of thought, similar to a union. In the example above, the figure demonstrates that the string starts with “10” or “11”. Falling off on a 0 in state C allows us to ignore those characters and truly focus on what we care about for that path. Free transitions and forked transitions are great tools for expanding our expressive power in a finite automata with ease. Expressing an OR expression in a DFA might require carefuly layering in the pathways in an intermingled fashion, but with an NFA, we can separate out the decisions easily.

We have seen three elements of non-determinism. We can fall off a machine, ending (rejecting) the processing line for that input. We can take a free transition, extending our processing line for an input (creating parallelism). We may also transition to another state on more than one input! Let’s practice some of the features of NFAs in the following exercise.

In the end our NFAs have a slightly different transition table and function. Now, our return could be a set of states, or no states at all. Our transition function may take us from any number of states on a given input symbol (taking free transitions immediately). In C++ code we might now have a processing transition function that looks like:

std::vector<Q> f(std::vector<Q>,A);

However, to formally describe the NFA itself, we can still use a transition table centered around a slightly differ. Let’s make a transition table for the NFA in Figure 4.3. This NFA has free jumps to two parallel processing segments. Those segments, in turn, have forked transitions. Can you sort out the language of this machine?

The transition table of Figure 4.3 is a bit more complex than our previous transition tables as shown in Figure 4.4. Notice that we have a row dedicated to free transitions, ~. In addition we notice that our transitions now leave us in a set of states rather than in a single state. Sometimes that set of states is empty - meaning we fall off the machine. This table looks a little different than our programming minded function from above. This is because, programmatically, we can take the free jumps immediately. However, in the transition table, we show them separately. Take a look at the transition table before we proceed to describing it formally with matematical language.

So, our old transition function was \(Q \times A \rightarrow Q\). Q is our set of states and A is our input alphabet. This is great for DFAs. For NFAs, our transition table requires \(A \cup \sim\) for potential input consideration, to include the free transition. The transition function now returns a set of states. The set of all possible subsets of a set is called the power set and we denote it as \(P(Q)\). Recall that \(\times\) is our cartesian product as seen in Section 2.5, our determinism section. We’ll tackle more on the power set later, but for now it suffices to say that it means we can land in some, all, or none of the states of Q. PUtting things together, our transition function is \(Q \times (A \cup \sim) \rightarrow P(Q)\). Processing then consists of, first looking up the free transitions and taking those immediately, then consuming the input symbol and looking up the transitions for that symbol. This process is repeated until we have consumed all the input symbols (or we hit a halt and accept if using the Ramsey variants). If any of the paths lead us to an accept state, then we accept the string.

The forks, or parallels in NFAs are sometimes called a guess. The machine is “guessing” whether it should be in state A or state B. Calling it a guess hints at how these sorts of machines are sometimes used in practice - with a backtracking algorithm. While it is outside of the scope of this book, state-space search is rife with pitfalls, and when developing with finite automata (or more likely, their equivalents) we must take care with our machines to avoid poor computational efficiency or performance. Specifially, “poor” guessing can lead to exponential growth in the processing of an NFA. Ultimately, however, we are limited by a certain number of states and branches, which is hinted at in our transition table by the use of the power set, \(P(Q)\).

4.2 Power Set

The power set of a set is the set of all possible subsets of that set, including the empty set. For example, if we have a set \(Q = \{A,B,C\}\), then the power set of \(Q\), denoted as \(P(Q)\), would be: \[P(Q) = \{\emptyset, \{A\}, \{B\}, \{C\}, \{A,B\}, \{A,C\}, \{B,C\}, \{A,B,C\}\}\]

Recall that the empty set, \(\emptyset\), is a set with no elements, {}. You’ll notice here that the power set of a set with three elements has 8 subsets. Let’s explore the power set in the following excercises.

Since the power set of a state set from an NFA encompasses all possible subsets of states, it can be used to represent the state of an NFA, encompassing all of its parallel processing into a single descriptor - the set of all states we are in at any particular point of processing the NFA.

A power set will have \(2^n\) subsets, where \(n\) is the number of elements of the original set. So a slightly complex NFA, like the one in Figure 4.3 with 6 states, could have as many as 64 subsets. At any given time in processing that NFA, we are in one of those 64 subsets. Let’s tackle that idea a bit more directly. Imagine that we will exhaustively track everywhere the machine can reach - every possible subset it can actually touch.

  • We start in state A, with free transitions to B and D (we take all free transitions immediately). Thus, the start configuration is {A, B, D}.
  • From {A, B, D}, if we read a 0, A falls off, B goes to C, and D goes to D Thus we are now in the configuration {C,D}.
  • From {A, B, D}, we read a 1, A falls off, B goes to B and F, and D goes to E. Thus we are now in the configuration {B,E,F}.
  • From {C,D}, if we read a 0, C goes to B and D goes to itself - leaving us in {B, D}.
  • From {C,D}, if we read a 1, C goes to C and D goes to E - leaving us in {C, E}.

Since any path that accept is an accepting path, every state that contains an accept state of the NFA, will be an accept state. So far that includes {B,E,F} (for both E and F), {C,E} (for both C and E), and {C,D} (for C).Let’s pause to see how this may look as a diagram thus far in Figure 4.5.

States are listed in simplified form in the diagram, such that “BEF” represents the set of states {B, E, F}. The diagram is already growing quite rapidly. After considering only two jumps, we could be in any one of four states. Can you follow the logic to finish the diagram?

The fully converted diagram of the NFA in Figure 4.3 using power set construction.

Now that we’ve tackled the conversion until we’ve run out of leads, let’s take a look at the diagram. We’ve arranged the diagram such that the three states that include E are grouped on the left. State E tracks an odd # of 1s. The two states with C are grouped along the bottom row and include the states that track an odd number of 0s. You’ll notice these 4 states are all accept states. The start state is somewhat isolated in the middle. Looking at the diagram as a whole, as we move from left to right, we’re flipping modality of 1 and as we move up and down we’re flipping the modality of 0. Lastly, strings that end in a 1 after an odd number of 0s are encoded by F. Looking at the diagram, an input of 1 always leads to an accept state. Thus if we end in a 1, we accept. Why does this work? Well, if we had seen an odd number of 0s, a 1 won’t change that and we’ll stay in an accept state. If we had seen an even number of 0s, we’ll be in the top half of the diagram. If we’re on the right side (even number of 0s), seeing a 1 will take us to {B, E, F}. That’s an odd number of 1s anyway, but it also ends in a 1 so it is an accept state. If we’re on the left side (looking at an odd number of 1s and already accepting), we’ll move to {B, D, F} and accept since F is an accept state. Using this power set construction is really quite an amazing way to convert any NFA into a DFA. The number of states can grow exponentially (the power set has size \(2^n\) afterall), and typically more states are required than in the NFA counterpart. Even so, it proves that NFAs and DFAs are equivalent in terms of the languages that they can recognize and it provides an algorithmic process for performing the conversion.
